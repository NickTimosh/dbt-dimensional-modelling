# dbt + BigQuery: AdventureWorks Project Setup

A step-by-step guide to setting up a dbt project on **dbt Platform**, connecting it to Google BigQuery and GitHub, and successfully materializing the first model.

## 1. Project Overview & Naming

| Component | Name | Purpose |
|---|---|---|
| Google Cloud Project ID | `dbt-adventureworks-2026-nt` | Cloud project hosting BigQuery |
| BigQuery Dataset | `adventureworks_dev` | Development schema for dbt models |
| dbt Platform Project | `AdventureWorks AE Practice` | Project in dbt Cloud |
| dbt Code Project | `adventureworks` | Project name in `dbt_project.yml` |
| GitHub Repository | [dbt-dimensional-modelling](https://github.com/NickTimosh/dbt-dimensional-modelling) | Source code and version control |
| Project Subdirectory | `adventureworks` | Root folder of the dbt project |

**Important naming conventions:**

- **dbt project name** — Identifies the dbt codebase; defined in `dbt_project.yml`.
- **dbt database** — Maps to the Google Cloud Project ID in BigQuery.
- **dbt schema** — Maps to a BigQuery dataset.
- **dbt alias / identifier** — Defines the final table or view name.
- **dbt profile** — Identifies the connection configuration; credentials are managed in dbt Platform.

A model's destination follows:

`database.schema.identifier`

Example:

`dbt-adventureworks-2026-nt.adventureworks_dev.connection_check`

## 2. Set Up Google BigQuery

### Step 1: Create a Google Cloud project

1. Open [Google Cloud Console](https://console.cloud.google.com/projectcreate).
2. Create a new project.
3. Set the Project ID to `dbt-adventureworks-2026-nt` (or another available unique ID).
4. Make sure BigQuery API is enabled and billing or an eligible sandbox configuration is available.

### Step 2: Create a dataset

In [BigQuery Studio](https://console.cloud.google.com/bigquery):

1. Select the new Google Cloud project.
2. Click **Create dataset**.
3. Configure:
   - Dataset ID: `adventureworks_dev`
   - Location: `US` (multi-region)
   - Default table expiration: None

This dataset will contain our development models.

### Step 3: Create a service account

Navigate to **IAM & Admin → Service Accounts**.

1. Create a service account named `dbt-adventureworks`.
2. Grant the required permissions:
   - `BigQuery Job User`
   - `BigQuery Data Editor`
   - `BigQuery Read Session User`
3. Create and download a JSON key from the service account's **Keys** section.

For this isolated learning project, project-level permissions simplify setup. In production, prefer least-privilege resource access.

**Security:** Never commit service account credentials to GitHub.

## 3. Configure dbt Platform

### Step 1: Create a dbt project

1. Open dbt Platform.
2. Navigate to **Account Settings → New Project**.
3. Name it `AdventureWorks AE Practice`.
4. Select **BigQuery** as the data platform.
5. Configure the connection using the service account JSON.
6. Verify that the Google Cloud Project ID is `dbt-adventureworks-2026-nt`.

### Step 2: Configure development credentials

Navigate to **Your Profile → Credentials**, then select the project.

Configure:

| Setting | Value |
|---|---|
| Authentication | Service Account JSON |
| Dataset | `adventureworks_dev` |
| Target | `default` |
| Threads | `4` |

Run **Test Connection**.

The connection test verifies authentication, but successful model execution must be checked separately.

## 4. Connect the GitHub Repository

Repository:

https://github.com/NickTimosh/dbt-dimensional-modelling

### Git Clone method

If GitHub reports **"Account in use"** because the GitHub identity is linked to another dbt account, use Git Clone.

1. Open **Account Settings → Projects → Repository**.
2. Select **Configure Repository → Git Clone**.
3. Enter the SSH URL:

```text
git@github.com:NickTimosh/dbt-dimensional-modelling.git
```

4. Copy the SSH deploy key generated by dbt.
5. Navigate to GitHub repository **Settings → Deploy keys**.
6. Add the key and enable **Allow write access** if you intend to commit from dbt Studio.
7. Save the configuration.

### Set the project subdirectory

Our dbt project is not located at the repository root.

Repository structure:

```text
dbt-dimensional-modelling/
└── adventureworks/
    ├── dbt_project.yml
    ├── packages.yml
    ├── models/
    └── seeds/
```

In dbt Platform project settings, configure:

```text
Project subdirectory: adventureworks
```

Do not initialize a new dbt code project because the repository already contains one.

## 5. Configure dbt_project.yml

File: `adventureworks/dbt_project.yml`

Ensure the project name and model configuration namespace match.

```yaml
name: 'adventureworks'
version: '1.0.0'
config-version: 2

profile: 'default'

model-paths: ["models"]
analysis-paths: ["analyses"]
test-paths: ["tests"]
seed-paths: ["seeds"]
macro-paths: ["macros"]
snapshot-paths: ["snapshots"]

clean-targets:
  - "target"
  - "dbt_packages"

models:
  adventureworks:
    marts:
      +materialized: table
      +schema: marts
```

**Key concepts:**

- `name` defines the dbt code project name.
- `profile` identifies the connection profile; dbt Platform manages the actual credentials.
- `models.adventureworks` must match the project name.
- `+materialized: table` configures table materialization for models in `models/marts/`.
- `+schema: marts` uses a custom schema for marts models.

By default, dbt appends the custom schema to the development target schema:

`adventureworks_dev_marts`

Models directly under `models/` continue using `adventureworks_dev` unless otherwise configured.

## 6. Create the First Model

Create a new SQL file:

`adventureworks/models/connection_check.sql`

```sql
{{ config(materialized='table') }}

select
    1 as id,
    'dbt and BigQuery connected' as status,
    current_timestamp() as created_at
```

This model creates a simple table without dependencies on external source data.

## 7. Validate and Run

Execute the following commands from dbt Studio.

**1. Install dependencies**

```bash
dbt deps
```

Downloads packages defined in `packages.yml`, including `dbt_utils`.

**2. Validate the connection**

```bash
dbt debug
```

Checks project configuration and warehouse connectivity.

**3. Parse the project**

```bash
dbt parse
```

Validates dbt project files, resource definitions, and configurations.

**4. Check model destination**

```bash
dbt ls --select connection_check --output json --output-keys "name database schema alias"
```

Expected output (relevant fields):

```json
{
  "name": "connection_check",
  "database": "dbt-adventureworks-2026-nt",
  "schema": "adventureworks_dev",
  "alias": "connection_check"
}
```

**5. Materialize the model**

```bash
dbt run --select connection_check
```

Executes the model in BigQuery and creates a physical table.

## 8. Verify in BigQuery

Navigate to BigQuery Studio and locate:

`dbt-adventureworks-2026-nt → adventureworks_dev → connection_check`

Execute:

```sql
select *
from `dbt-adventureworks-2026-nt.adventureworks_dev.connection_check`;
```

Expected result:

| id | status | created_at |
|---|---|---|
| 1 | dbt and BigQuery connected | Current timestamp |

The initial dbt + BigQuery setup is now complete.

## 9. Troubleshooting Notes

| Issue | Likely Cause | Solution |
|---|---|---|
| Invalid project ID | Dataset name used as BigQuery project ID | Check `database` and connection configuration |
| Compilation succeeds, but run fails | SQL compilation doesn't guarantee successful warehouse execution | Inspect `dbt run` errors and permissions |
| Model materializes in unexpected dataset | Different development target schema or `+schema` configuration | Inspect `dbt ls --output-keys` |
| GitHub account already in use | GitHub identity linked to another dbt account | Use Git Clone with a deploy key |
| dbt project configuration errors | Project name and model config namespace don't match | Align `name` and `models` in `dbt_project.yml` |
| Project files not found | Incorrect repository subdirectory | Set Project subdirectory to `adventureworks` |
